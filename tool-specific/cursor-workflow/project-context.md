# Project Context — How I Set Up Context for Cursor

> Documents exactly how project context was configured for Cursor across this project,
> so the approach is reusable and auditable.

---

## 1. Persistent Rules (`.cursor/rules/`)

A single always-applied rule file was created at `.cursor/rules/00-project-context.mdc`.
It is loaded automatically at the start of every Cursor session and contains:

- **Project purpose:** Databricks Medallion Architecture pipeline for e-commerce sales,
  as part of a formal AI-capability assessment
- **Stack:** Python, PySpark, SQL, Delta Lake, Databricks Free Edition (serverless)
- **Data:** Three CSV sources — customers (10,000 rows), orders (100,000 rows), products (500 rows)
- **Hard rules enforced by the rule file:**
  - Silver layer must flag bad rows via `quality_check_result`, never delete them
  - Every function/script needs a docstring explaining purpose, inputs, outputs
  - snake_case naming for all Python/SQL identifiers
  - No architectural decisions made silently — surface as questions or documented assumptions
  - No real PII — all data is synthetic
- **Source of truth reference:** `docs/assessment-requirements.md`

This means every new Cursor session starts with the full project mandate without
needing to re-paste context manually.

---

## 2. Primary Reference Document

`requirements-analysis.md` (project root) is the locked planning document.
It contains:
- All 38+ functional requirements (FR-01 to FR-05d)
- 10 non-functional requirements
- 7 documented gaps with resolutions (G-01 to G-07)
- 18 locked assumptions (A-01 to A-18)
- The complete repository scaffold (Section 4)
- The phased build plan with "done looks like" criteria (Section 6)
- Resolved environment decisions: Unity Catalog catalog=`workspace`,
  schema=`ecommerce_medallion`, volume=`raw_data`

When starting any significant coding session, the first instruction to Cursor
references the relevant section of `requirements-analysis.md` to anchor the task.

---

## 3. Prompt History as Ongoing Context

The `ai-prompts/` directory contains one file per activity area. Before starting
a new phase, the relevant `ai-prompts/<phase>.md` file is referenced so Cursor
has visibility of what has already been attempted, accepted, changed, or rejected
in prior sessions on the same topic.

---

## 4. Unity Catalog Environment Context

Provided explicitly at the start of Bronze and Silver sessions:

```
Environment: Databricks Free Edition (serverless)
Unity Catalog:
  Catalog : workspace
  Schema  : ecommerce_medallion
  Volume  : /Volumes/workspace/ecommerce_medallion/raw_data/
Table reference pattern: workspace.ecommerce_medallion.<table_name>
```

---

## 5. What Information Was NOT Shared with Cursor

- No real customer names, emails, or order data
- No Databricks workspace credentials or tokens
- No internal system architecture beyond what the assessment document describes
- All data used in prompts is the synthetic seed data generated by us

---

## 6. Context Re-establishment Pattern (per session)

At the start of each new Cursor session on this project:
1. The `.cursor/rules/` file is auto-loaded (no action needed)
2. For coding tasks: reference `requirements-analysis.md` Section relevant to current phase
3. For continuation tasks: reference the relevant `ai-prompts/<phase>.md` to show prior work
4. Provide the Unity Catalog environment block if writing ingest/transform scripts
